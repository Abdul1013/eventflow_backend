# EventFlow Load Test — H2 & H3 Validation

Locust-based load test suite that validates the two performance hypotheses:

| Hypothesis | Criterion |
|------------|-----------|
| **H2** — check-in throughput | P99 latency of `POST /checkin/scan` ≤ 7 000 ms under 2 500 concurrent VUs |
| **H3** — HMAC security under load | 5xx error rate ≤ 0.5 % (forged tokens return `INVALID_TOKEN`, never a server crash) |

---

## Prerequisites

```bash
pip install locust asyncpg "redis[asyncio]" bcrypt PyJWT
```

Locust ≥ 2.20 is required for `LoadTestShape.tick()` support.

---

## Environment Variables

Set these **before** running the seed script or locust:

| Variable | Required | Description |
|----------|----------|-------------|
| `LOAD_TEST_API_URL` | No | API base URL (default `http://localhost:3001`) |
| `DATABASE_URL` | **Yes** | PostgreSQL connection string — must point to the **test** DB |
| `REDIS_URL` | No | Redis URL (default `redis://localhost:6379`) |
| `HMAC_SECRET` | **Yes** | Must match `HMAC_SECRET` in the running API |
| `JWT_ACCESS_SECRET` | **Yes** | Must match `JWT_ACCESS_SECRET` in the running API |
| `LOAD_TEST_STAFF_TOKEN` | No | Override staff JWT (auto-generated by seed if absent) |

> **Warning:** `DATABASE_URL` should point to a **separate test database**, not the production DB.  The seed script inserts 2 500+ rows and the cleanup script deletes them by pattern.

## Setup

### 1. Start the API

```bash
# From the monorepo root
pnpm --filter api dev
# Default port 3000; set LOAD_TEST_API_URL=http://localhost:3000 to match
```

### 2. Seed test data

```bash
cd apps/api/tests/load

python fixtures/seed_load_data.py
```

This creates:
- 1 admin + 1 staff + 2 500 attendee users (email `loadtest_{i}@eventflow.test`, password `LoadTest1!`)
- 1 venue + 1 ONGOING event + 1 ticket type (capacity 3 000, 2 500 pre-sold)
- 2 500 HMAC-signed QR tokens seeded into Redis (24 h TTL)

Outputs:
- `fixtures/tokens.json` — `[{token, ticketId, userId}]` for 2 500 tokens
- `fixtures/event_info.json` — event/venue/user IDs + staff/admin JWTs

## Running the Load Test

### Headless — CI / academic report

```bash
locust -f locustfile.py \
  --headless \
  --users 2500 \
  --spawn-rate 41 \
  --run-time 6m \
  --html results/h2_report.html
```

This uses the custom `EventFlowLoadShape` (ramp 0→2 500 over 60 s, hold 5 min).
The `--users` and `--spawn-rate` flags are overridden by the shape; include them
to satisfy Locust's CLI validation.

### Interactive UI — development / debugging

```bash
locust -f locustfile.py
# Open http://localhost:8089
# Set Host = http://localhost:3001
# Users = 2500, Spawn rate = 41
```

## Load Shape

```
VUs
2500 │        ┌────────────────────────────────────┐
     │       /                                      │ Stop
     │      /  Ramp (41 VUs/s)    Hold 5 min        │
   0 │─────/─────────────────────────────────────────▶ time
     0    60 s                                    360 s
```

**User mix** (by Locust weight):

| Class | Weight | VUs | Role |
|-------|--------|-----|------|
| `ScanUser` | 80 | ~2 000 | Staff scanning QR codes — H2 target |
| `BrowseUser` | 15 | ~375 | Public event browsing — background reads |
| `PurchaseUser` | 5 | ~125 | Ticket purchases — concurrent DB writes |

## Cleanup

```bash
python fixtures/cleanup.py
```

Removes:
- All `qr:{token}` keys from Redis listed in `tokens.json`
  (**does not** flush the entire Redis instance)
- All DB rows created by the seed script (by event ID and email pattern)
- `fixtures/tokens.json` and `fixtures/event_info.json`

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `FileNotFoundError: tokens.json` | Seed not run | `python fixtures/seed_load_data.py` |
| All scans return `INVALID_TOKEN` | Wrong `HMAC_SECRET` | Ensure env var matches running API |
| All scans return `401` | Expired or wrong staff JWT | Re-run seed or set `LOAD_TEST_STAFF_TOKEN` |
| `asyncpg.InvalidPasswordError` | Wrong `DATABASE_URL` | Check connection string |
| Redis pipeline fails | Redis not reachable | Check `REDIS_URL` and Redis service |
| P99 >> 7 000 ms | API or DB under-resourced | Profile with `pnpm --filter api dev` logs |
